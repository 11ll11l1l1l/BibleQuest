# BibleQuest V7 — one CLEAN master, deterministic presentation and five-agent QA
Effective 2026-10-11 JST. **Governs new QA instructions and artwork direction; production-schema/runtime migration is separately gated.**
Source: owner-authorized instructions for contemporary subjects, thematically relevant alternatives, one original raster per canonical ID, live localized text, and repeatable focal-aware cropping.

## Production contract
- One canonical content ID -> **one original, immutable CLEAN** PNG/WebP master. Generate no independent TYPE or THUMB scene. Output family master geometry: Feeling **1024x1024 1:1**, Need/devotional **768x960 4:5**, Home **1536x864 16:9**; real raster bytes, at most 10 MB, existing ratio tolerance. Preserve genuine native detail, no artificial upscale, SVG, collage, stock-copy, or generated text.
- Depict believable **contemporary people** and ordinary settings. Prefer the individual construction chapter's activity, but a distinct everyday action can earn `THEMATIC_ALTERNATIVE` if independently reviewable pixels faithfully express the full source's central truth. Record the precise visual evidence and source-grounded rationale. Generic moods, unrelated scenery, Scripture contradictions, stereotypes or misleading symbolic promises remain FAIL. Never rewrite canonical content or historic shot brief to justify an alternative.
- One original art task per canonical ID. TYPE is normally **live accessible localized DOM text** over or adjacent to the CLEAN (exact source title and reviewed reference, independently QA'd contrast/legibility/RTL/long-word behavior where relevant). THUMB is a **display profile** using the same CLEAN and crop metadata, not another generation task. Small deterministic build-time/WebP renditions from CLEAN are allowed for download/offline performance, not required creative variants.
- Store a source hash and unique provenance for each master, `focalPoint:{x,y}` normalized to 0..1, `textSafeRegion`, and optionally versioned per-surface crop metadata **only after** schema support is implemented. Use existing allowed and immutable safe paths.

## Fixed crop geometry — what is and is not constant
For a master size (W,H) and a fixed display box (w,h), `object-fit:cover` uses scale `s=max(w/W,h/H)`. Rendered dimensions are `(sW,sH)`; the clipped horizontal/vertical excess is `(sW-w,sH-h)`. A fixed `object-position` (px,py in 0..1) determines where that excess is removed. With unchanged master bytes, fixed box dimensions/ratio, fit mode and object-position, the result is **deterministic** across runs. Source same aspect as box => no cropping, only scaling. A square-versus-portrait container needs a **different crop**; identical fixed dimensions alone do NOT guarantee visible faces, hands, text-safe region, or narrative will survive.
- Choose and persist focal placement **per master**, not one global center point for every picture. Start with `object-position: ${"{x*100}"}% ${"{y*100}"}%` from validated focal metadata; use explicit audited per-surface override only when necessary. Keep critical action and people in the intersection of required viewport crop windows. If impossible, keep the intended family ratio, change display `contain`/letterbox design, or HOLD the surface—not the sound master.
- Use a reproducible profile name and target ratio (Feeling square, Need/devotional portrait, Home wide, thumbnail sizes). Viewport resize can change the **pixel crop** when the container's ratio changes. Review 320, 390, 430 and 800 CSS pixels, 100px thumbnails, zoom and long translated titles. A stored mobile/desktop crop profile may be needed.
- No “split a collage into three images” salvage. Cut/resample a **single valid source** only; cropping cannot cure the wrong story, insufficient source pixels, or inauthentic anatomy.
- Runtime CSS crop saves storage but **does not save transfer bytes**. When performance/offline budgets demand it, derive a deterministic thumbnail once in build time from the SAME accepted master (store parent SHA, recipe and derivative SHA). Never recompute huge bitmap crops continuously on each client, and never pay an external processing service unless authorized.

## Five-agent QA: evaluate real master and rendered presentations, not 3 fabricated scene files
1. **Scene / Scripture:** inspect full source, reference context, real pixels; classify `EXACT_SCENE`, `THEMATIC_ALTERNATIVE` (document truth/action connection), or `UNRELATED` (FAIL). Verify modern cast, one scene, no contradiction.
2. **Rights / wording:** verify generation provenance, image rights, immutable source SHA, approved live title/reference/locale against current content, no embedded text/copyright misuse.
3. **Technical / responsive:** decode master PNG/WebP; compare actual bytes/dimensions/SHA, true minimum by family, focal metadata bounds; verify actual built crop windows, text overlay contrast/fit, 100px preview, 320/390/430/800, served-byte identity and network/offline payload. Missing built proof => HOLD.
4. **Uniqueness / visual:** compare prior approved, pending and rejected artworks, anatomy, thematic distinctness, crop-safe framing, safe overlay placement, no repetitive pose/environment.
5. **Coordinator:** independently reconcile role proofs to same canonical ID, immutable source, exact PR head and optional derivative identity. Never infer another agent's PASS or promote while any required gate is HOLD.

QA-only reviewers never render, retouch, crop/export or regenerate pixels. User-invoked manual image chats own creating CLEAN and deterministic exports. On true FAIL reject/delete only failed unapproved candidate bytes after checking shared references; persist digest/scene/reason tombstone, continue to NEXT item same run. On HOLD retain genuine candidate safely, record missing evidence and proceed to next. Do not delete approved CLEAN masters or legacy TYPE/THUMB.
